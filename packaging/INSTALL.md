# Install the community node

Bundles include the Go node and pinned Rust proof helper, plus the Codex templates and a Linux user-service template. Supported build targets are Linux amd64 on Ubuntu 24.04, macOS arm64 and macOS amd64. Other Linux distributions have not been validated. Native CI uses the corresponding [GitHub-hosted runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners). No release or production dispatch is enabled by building a bundle.

Download the bundle for your platform and its archive checksum from the reviewed repository release or CI artifact. Verify the archive before extracting it with `sha256sum -c BUNDLE.tar.gz.sha256` on Linux or `shasum -a 256 -c BUNDLE.tar.gz.sha256` on macOS. These checks detect corruption; their trust comes from the source where you obtained them. Private repository downloads require repository access.

Extract the archive, enter its directory and run `./install.sh`. It verifies the fixed bundle files, installs a version under `~/.local/lib/scarlett-node/versions/`, and switches the active version atomically. Both executables are linked from `~/.local/bin/`; add that directory to PATH. Reinstalling the same version is allowed only when its contents match. An unrelated executable is never overwritten. You can pass an absolute installation root and bin directory as the two arguments.

Copy `node.env.example` to `~/.config/scarlett-node/node.env`, keep it private with mode 0600 and edit the absolute local credential paths, chosen services and coordinator/verifier addresses. The verifier placeholder deliberately cannot serve work. X needs a private session JSON file without a proxy override. Your provider sessions stay local. Supply either Codex, X or both; remove the unused service from `SCARLETT_SERVICES`. In a shell, export the settings before using `scarlett-node pair` and its hidden prompt, then `scarlett-node run`.

For the default Linux installation, copy `scarlett-node.service` to `~/.config/systemd/user/`, run `systemctl --user daemon-reload`, then `systemctl --user enable --now scarlett-node`. Pair first using the same configuration and state directory. The installer does not start services or change login persistence. Custom installation paths need corresponding edits to the unit. On macOS, run the node in the foreground or use your own process supervisor.

Before an upgrade, request drain, wait for zero in-flight work and stop the node. Install the new bundle, then restart using the same state directory. Drain persists; use `scarlett-node resume` when ready. To roll back, rerun the previous version's `install.sh` with the same installation paths. Keep the identity and attempt journal throughout upgrades and rollbacks; unresolved attempts must reconcile with the coordinator before further work. Local status is an observation, not proof acceptance or payment settlement.
